# Next.js + Better Auth setup

`setup.sh` creates a Next.js application with email/password authentication, Prisma 7, and a local MySQL database managed by Docker Compose.

## Prerequisites

- Bash, OpenSSL, and standard Unix utilities.
- Node.js and npm compatible with the Next.js and Prisma versions being installed.
- Docker with Docker Compose (`docker compose`), with the Docker daemon running.
- Git, with your commit name and email configured.
- Internet access to download packages, and port `3306` available for MySQL.

## Usage

Run the script from the directory where you want to create the application, using the path to your copy of `setup.sh`:

```bash
bash /path/to/setup-script/setup.sh my-app
```

Use a new, simple folder name such as `my-app`. The script also uses this argument to name the Docker container (`my-app-dev`), so avoid passing a path containing slashes.

The script creates and enters the folder, installs dependencies, writes application files, starts MySQL, formats the project, and creates an initial Git commit. It stops on errors and leaves any files already created in place; it is intended for fresh projects rather than rerunning over an existing application.

## What it creates

- A Next.js App Router project with TypeScript, Tailwind CSS, ESLint, and npm.
- Prisma CLI, client, and MariaDB driver adapter constrained to major version 7 for compatibility with Better Auth.
- Better Auth email/password authentication with cookie support and an API route at `/api/auth/[...all]`.
- A home page showing the current authentication status, plus `/signin`, `/signup`, and `/signedout` pages.
- Server actions for signing in, signing up, and signing out, with Zod form validation.
- Session helpers, including `getCurrentUser` and `requireUser`, and a shared Prisma client.
- A Prisma schema generated by the Better Auth CLI and a generated client in `generated/prisma`.
- `.env` with a randomly generated authentication secret, plus `.env.example` with a placeholder secret.
- A MySQL 8 Docker Compose service, a persistent database volume, and initialization SQL.
- Prettier configuration and VS Code recommendations for Prisma, Prettier, and OpenAI ChatGPT.
- An initial Git commit named `Initial project setup`.

Next.js and the Better Auth schema CLI use their `latest` releases. Most other dependencies are also unpinned, so generated projects can change as new versions are published.

## Local database and environment

The MySQL container exposes port `3306` and creates three databases:

| Database | Purpose |
| --- | --- |
| `app_dev` | Application development |
| `app_test` | Reserved for testing; no test runner is configured |
| `app_shadow` | Prisma migration shadow database |

The generated development credentials are `myuser` / `mypass`, with root password `rootpass`. These defaults are for local development.

The generated `.env` contains:

```dotenv
BETTER_AUTH_SECRET="<randomly generated secret>"
BETTER_AUTH_URL=http://localhost:3000
DATABASE_URL="mysql://myuser:mypass@127.0.0.1:3306/app_dev"
SHADOW_DATABASE_URL="mysql://myuser:mypass@127.0.0.1:3306/app_shadow"
NODE_ENV="development"
PORT=3000
```

## After setup

The script generates the schema and client but does not apply database migrations or start the development server. Review `prisma/schema.prisma`, then run:

```bash
cd my-app
npx prisma migrate dev --name init
npx prisma generate
npm run dev
```

Wait for MySQL to finish starting before running the migration. Open `http://localhost:3000` and use **Sign up** to create an account.

## Stopping or removing the database

Run these commands from the generated project folder. Stop the database while retaining its data:

```bash
docker compose down
```

Start it again:

```bash
docker compose up -d
```

To remove the database volume and permanently delete its local data:

```bash
docker compose down -v
```
